# 做了没 · 安卓测试版

本目录是独立的安卓项目，不改变根目录的网页版。主界面沿用网页的黑色布局；APK 内包含离线页面，原生端负责精确定时、响铃、振动、推迟和保存记录。Android 8.0 及以上。

## 云端打包

在 GitHub 仓库的 Actions 中选择 **Android APK**。提交本目录修改会自动构建；工作流进入默认分支后也可以使用 Run workflow 手动运行。构建成功后，下载 **zuolemei-android-apk** 附件，解压得到 `zuolemei-0.1.0-test.apk`。附件保留14天，可以重新运行构建。

手机首次安装时，按系统提示允许对应来源安装应用。打开后开启通知、闹钟和提醒权限；全屏提醒单独授权。请检查闹钟音量。

这是调试签名测试包，没有上架。可在仓库 Secrets 配置 `ANDROID_DEBUG_KEYSTORE_BASE64` 保存固定的 Android 调试密钥，以便不同构建覆盖安装；未配置时每个新构建可能签名不同，需要卸载旧版才可安装，卸载会删除本地记录。正式分发前应另行配置私密的正式签名和更新方案。

## 功能与限制

- 5/15/25/45分钟、自定义1至10080分钟。
- 输入框历史建议只取本 App 已完成事项，去重、最近优先。
- 使用系统 `setAlarmClock`，页面关闭后仍由系统触发。
- 原生通知和锁屏页面提供完成、推迟；响铃最多5分钟，然后标记未完成。
- 同时到期的提醒依次响铃；完成或推迟一条后进入下一条。
- 重启/更新后恢复提醒；已经过期的提醒安排在恢复后约3秒触发。
- 数据只存在本机 App 内；网页浏览器里的记录不会自动导入。
- 暂不包含每日/循环提醒、自定义音频、云同步或付费。
- 原生端使用 SharedPreferences 持久化 JSON，并用同步入口串行处理任务更新。尚未迁移至数据库，后续记录量增加时可以迁移。
- 强行停止、关机、权限被撤销等情形不能保证提醒；厂商省电策略需要实测。
- 当前倒计时基于系统墙上时间，手动更改系统时间会影响提醒。

## 真机验收

1. 设置1分钟提醒，回到桌面并锁屏，检查响铃、振动、通知。
2. 点击通知中的推迟10分钟，确认声音停止、时间更新，之后再次响铃。
3. 点击完成，确认只写入一次完成记录，输入框出现该历史建议。
4. 同时设置两个提醒，完成第一项后确认第二项可处理。
5. 添加提醒后重启手机，解锁并等待；检查恢复及过期提醒。
6. 分别测试划掉最近任务、省电模式、通知关闭、闹钟权限关闭。
7. 测试手机无网络时添加、触发和保存记录。

云端编译和静态检查通过不代表这些真机行为已经验证。
